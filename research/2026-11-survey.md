# What popular agent skills reach for: a Cleat survey

**Date:** 13 November 2026
**Tool:** cleat 0.1.0

## Scope

20 repositories that publish the most-installed agent skills, chosen from the
skills.sh install leaderboard plus widely used vendor skill repositories.
These repositories contain 419 skill folders. 64 are exact copies of another
skill in the same repository (bundled into several plugins), leaving **355
unique skills**.

Every skill was copied as files only. Nothing was installed or run.

## Findings

| Measure | Result |
|---|---|
| Skills containing any outside link | 230 of 355 (65%) |
| Skills that tell the agent to read, download or run outside content | 154 (43%) |
| ... tell the agent to read or follow an outside page | 147 (41%) |
| ... download something | 38 (11%) |
| ... download something and run it as code in one step | 5 (1%) |
| Outside links the agent is told to act on | 1,406 |
| ... of which are pinned to a fixed version of the content | **0** |
| Skills that run a package on demand (npx, uvx and similar) | 122 (34%) |
| ... with no fixed version | 120 (34%) |
| On-demand package runs pinned to an exact version | 4 of 224 |
| Package names checked against npm and PyPI | 266 |
| ... that do not exist (open to name squatting) | 0 |
| Links hidden from a normal read | 1 (template comments, benign) |

### What this means

**Four in ten popular skills hand part of their behaviour to content that
lives somewhere else, and none of that content is pinned.** Every one of the
1,406 outside links an agent is told to act on can change without the skill
changing. This is not a sign of bad intent: these are mostly official vendor
documentation links. It does mean that reviewing these skills' files reviews
only part of what they do.

**A third of skills run packages on demand at whatever version is newest.**
Pinning was almost absent: 4 of 224 on-demand package runs specify an exact
version.

**Downloading a script and running it straight away appears in official vendor
skills.** Five skills pipe a vendor install script straight into a shell. The
sources are reputable (Stripe, Microsoft, Chocolatey), but the pattern gives
whoever controls that URL, or its DNS, control of the machine.

**No hidden malicious content was found.** The one hidden reference is a
documentation link inside an HTML comment in a Microsoft template file.

### Skills Cleat rated high risk (11)

These are patterns that deserve a human look. None is evidence of malice.

| Skill | Why |
|---|---|
| stripe/ai: stripe-directory, stripe-projects | Downloads the Stripe CLI install script and pipes it to `sh`. |
| microsoft: azure-deploy, azure-prepare | Downloads the azd install script and pipes it to `bash`. |
| microsoft: microsoft-foundry | Tells the agent to follow sample pages that themselves pipe an installer to `bash` (a second-hand instruction). |
| microsoft: azure-diagnostics | A troubleshooting step runs `setenforce 0`, which switches SELinux off. |
| hashicorp: windows-builder | PowerShell downloads and executes the Chocolatey installer. |
| get-convex: convex-improve-convex-plugin | Pipes a script from a placeholder host into `bash`, passing a summary of the session. |
| mattpocock: software-factory | Tells the agent to follow a GitHub project page whose install step pipes a script from a branch into `bash`. |
| anthropics: claude-api | Removes the macOS quarantine flag from the CLI it installs. |

## Limits of this survey

- **Remote documentation was not fetched.** The network used for this survey
  could reach GitHub, npm and PyPI only, so 360 GitHub-hosted links were
  fetched and checked, and vendor documentation sites were not. The figures
  above describe what skills point to, not what is at the other end today.
- Pattern rules catch known shapes. They do not judge intent.
- Cleat does not run skills. Run-time behaviour is out of scope.
- Leaderboard data came from a third-party tracker and changes daily.

## False positives fixed during the survey

Running Cleat across 355 real skills exposed seven rules that were too broad.
Each was fixed and given a regression test before the final run:

1. Port checks using `/dev/tcp` were read as reverse shells.
2. Local development addresses (`127.0.0.1`) were treated as suspicious IPs.
3. Ordinary API calls that send data were rated high.
4. `curl ... | python -m json.tool` (formatting output) was read as running code.
5. Warnings that quote `curl | sh` were read as instructions to do it.
6. Case-blind matching read curl's `-D` (save headers) as `-d` (upload), and
   `<env>` placeholders as environment harvesting.
7. Comments in scripts ("npx stays the same") were read as install commands.

## Reproduce

```bash
git clone --depth 1 https://github.com/<owner>/<repo>   # for each repository above
node skills/cleat/scripts/cleat.mjs scan <skill-folder> --json
```

Count a skill once when several folders have the same `skill.treeSha256`.
