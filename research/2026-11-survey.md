## Scope

skills.sh install leaderboard plus widely used vendor skill repositories.
These repositories contain 419 skill folders. 64 are exact copies of another
skill in the same repository (bundled into several plugins), leaving **355
unique skills**.

## Findings

The labels Cleat gives each link come from pattern rules. We checked them by
hand on random samples (see [Hand check](#hand-check)); the hand-checked
figures are the ones to quote.

| **Outside links, counted once per skill / pinned by commit hash** | **4,273 / 13 (all in one skill)** |
| Skills containing any outside link | 230 of 355 (65%) |
| Skills that tell the agent to read, download or run outside content | 154 (43%) |

### What this means

**Four in ten popular skills hand part of their behaviour to content that
lives somewhere else, and none of that content is pinned.** Every one of the
1,406 outside links an agent is told to act on can change without the skill
changing. This is not a sign of bad intent: these are mostly official vendor
documentation links. It does mean that reviewing these skills' files reviews
only part of what they do.

**A third of skills run packages on demand at whatever version is newest.**
Pinning was almost absent: 4 of 224 on-demand package runs specify an exact
version.

**Downloading a script and running it straight away appears in official vendor
skills.** Five skills pipe a vendor install script straight into a shell. The
sources are reputable (Stripe, Microsoft, Chocolatey), but the pattern gives
whoever controls that URL, or its DNS, control of the machine.

**No hidden malicious content was found.** The one hidden reference is a
documentation link inside an HTML comment in a Microsoft template file.

### Ratings

Cleat rates a link it cannot reach as worth review. On the survey network
that flag described our connection, not the skills, so it was set aside
before ratings were counted. Cleat's unadjusted output was 142 no red flags,
201 review and 12 high risk; the one extra high-risk rating came from that
flag alone. The figures above use the adjusted counts.

### Skills rated high risk (11)

"High risk" is Cleat's label for what a step could do if its source were compromised, not a judgement of the skill or its publisher. Each case below was checked by hand and has a documented, legitimate purpose; none is evidence of malice.

| Skill | Why |
|---|---|
| stripe/ai: stripe-directory, stripe-projects | Downloads the Stripe CLI install script and pipes it to `sh`. |
| microsoft: azure-deploy, azure-prepare | Downloads the azd install script and pipes it to `bash`. |
| microsoft: microsoft-foundry | Links to sample pages whose install step pipes the azd installer to `bash` (a second-hand instruction). |
| microsoft: azure-diagnostics | A troubleshooting step runs `setenforce 0`, which switches SELinux to permissive until the next reboot. |
| hashicorp: windows-builder | PowerShell downloads and executes the Chocolatey installer. |
| get-convex: convex-improve-convex-plugin | Pipes a script from a configured service into `bash` to send the session transcript for review. It asks the user's consent first. |
| mattpocock: software-factory | Links to a GitHub project page whose install step pipes a script from a branch into `bash`. |
| anthropics: claude-api | Removes the macOS quarantine flag from the CLI it installs. |
| expo: expo-skill-eval | Offers to run sub-agents with `--dangerously-skip-permissions` (it asks the user first). |

## Hand check

Seeds and every judgement are in [`2026-11-validation.json`](2026-11-validation.json).

**Links.** Random samples of 100 links Cleat labelled acted on, and 100 it
labelled mentions, were each put in one of four groups:

| Hand-checked group | Labelled acted on | Labelled mention |
|---|---|---|
| Explicit pointer or command | 62 | 28 |
| Reference link without a directive | 12 | 39 |
| Service endpoint, tool input or user-specific page | 10 | 10 |
| Not acted on by the agent | 16 | 23 |

The labels are imperfect both ways, with a margin of about ten points per
share. Scaled up, roughly 1,700 links carry an explicit pointer (about 1,400
to 2,000), so Cleat's 1,406 is the right size but single labels are
approximate.

**Skills.** Of the 154 skills Cleat counted as acting on outside content, 121
contain at least one explicit pointer or command, 15 only reference links, 7
only endpoints or tool inputs, and 11 none. At least 8 of the 76 skills it
counted as mention-only contain an explicit pointer it missed. Floor: 129
skills (36%).

**Packages.** Of 40 package commands drawn at random, 17 download and run a
package from the registry, 21 most likely run a tool the project already has
installed, and 2 were words in prose read as commands.

**Pinning.** 13 of 4,273 outside links are pinned by commit hash, all in one
skill (azure-ai, citing source files). One acted-on link names an exact
package version on a CDN (`world-atlas@2.0.2`), which Cleat's rule does not
count as pinned.

## Limits of this survey

- **Most remote content was not fetched.** The network used for this survey
  could reach GitHub, npm and PyPI but not most vendor documentation sites.
  387 links were fetched and checked, almost all on GitHub, but only 97 of
  them are links the agent acts on (7% of 1,406); the rest are mentions. The
  figures above describe what skills point to, not what is at the other end
  today.
- Pattern rules catch known shapes. They do not judge intent.
- Cleat does not run skills. Run-time behaviour is out of scope.
- Leaderboard data came from a third-party tracker and changes daily.

## False positives fixed during the survey

Running Cleat across 355 real skills exposed seven rules that were too broad.
Each was fixed and given a regression test before the final run:

1. Port checks using `/dev/tcp` were read as reverse shells.
2. Local development addresses (`127.0.0.1`) were treated as suspicious IPs.
3. Ordinary API calls that send data were rated high.
4. `curl ... | python -m json.tool` (formatting output) was read as running code.
5. Warnings that quote `curl | sh` were read as instructions to do it.
6. Case-blind matching read curl's `-D` (save headers) as `-d` (upload), and
   `<env>` placeholders as environment harvesting.
7. Comments in scripts ("npx stays the same") were read as install commands.

## Reproduce

```bash
git clone --depth 1 https://github.com/<owner>/<repo>   # for each repository above
node skills/cleat/scripts/cleat.mjs scan <skill-folder> --json --max-fetch 1000
```

Count a skill once when several folders have the same `skill.treeSha256`.
Before counting ratings, set aside the flag Cleat raises for links it could
not reach (see Ratings).

The survey was first run with a pre-release build, then repeated in full with
the public 0.1.1 release. Every figure above was identical in both runs except
the number of links fetched, which rose to 387 once the fetch limit was raised
(0.1.1 fetched at most 40 links per skill by default). No link fetched in the
first run failed in the second. From 0.1.2, every link a skill tells the agent
to act on is fetched by default, so the `--max-fetch` flag is no longer needed
for a survey of this size.
